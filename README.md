## 三、ReAct 闭环自愈修复记录（任务四）

### 故障现场

在配套演练页面 `03_buggy_practice/index.html` 中点击"重置摆动"按钮，控制台抛出：

```
Uncaught ReferenceError: resetAnimation is not defined
    at HTMLButtonElement.onclick (index.html:68:15)
```

### ReAct 三步闭环

- **Reasoning（思考）**：`ReferenceError: xxx is not defined` 属于运行时作用域错误。按钮通过内联 `onclick="resetAnimation()"` 调用，但该函数定义在脚本内部作用域（或存在命名拼写不一致），导致全局作用域中找不到该标识符。
- **Action（行动）**：修复函数作用域与事件绑定关系——弃用脆弱的内联 `onclick`，改用 `document.getElementById("resetBtn").addEventListener("click", ...)` 将事件绑定到函数声明处，同时确保函数在脚本顶层声明。
- **Observation（观察）**：刷新页面，点击重置按钮摆球精准复位到 45°，按 F12 检查 Console，0 红色报错，自愈闭环完成。

### 经验沉淀

情绪化的"怎么坏了，重写一遍"只会诱发 AI 盲目重构、引入新 Bug；而把**完整错误堆栈 + 复现步骤 + 验收标准**作为证据喂给 AI，才能触发"思考-行动-观察"的精准外科手术式修复。**证据驱动排错**是人机协同提效的关键杠杆。

## 四、人机协同三反思

### 1. 意图清晰度反思

在任务三让 AI 追加滑块时，我第一版提示词只写了"加三个滑块控制参数"，结果 AI 生成的滑块只改了界面数值标签、没有真正绑定到物理变量——结果不符合预期。回看提示词，缺少了**验收标准**这一要素：我没有写明"拖动滑块时物理模拟必须即时响应"。补齐方式：在增量 Prompt 中明确【验收标准】"拖动滑块物理模拟即时响应且阻尼自然衰减，点击重置按钮复位，控制台 0 报错"，并补充【技术约束】"仅做局部增量修改，勿破坏 Canvas 渲染"。第二轮 AI 输出一次通过。教训：四段式（角色/目标/约束/验收标准）缺一不可，验收标准是防"假完成"的合同条款。

### 2. 闭环控制反思

遇到控制台 `ReferenceError` 报错时，我的定位流程是：按 F12 打开 DevTools → Console → 复制完整红色错误堆栈（含文件名与行号）→ 作为【报错证据】提交给 AI。AI 的修复思路我完全看懂了：它没有重写整个文件，而是 Reflection 定位到"内联 onclick 调用了不在全局作用域的函数"这一根因，将事件绑定方式从内联 HTML 属性改为 `addEventListener`，属于修改**边界条件**（作用域边界）而非碰物理公式。我也主动验证了物理公式本身：`α = -(g/L)·sin(θ) - k·ω` 在阻尼增大时摆幅指数衰减、g 增大时周期变短，与滑块的实测行为一致，确认修复没有引入物理层面的回归。

### 3. 主体地位确认

作为 HOTL 的产品总设计师，由我决定的核心决策包括：**产品形态**（单文件、双击即运行）、**验收边界**（0 报错、45° 复位精度、参数取值范围）、**迭代节奏**（MVP 先跑通再小步加交互，拒绝大爆炸）、**质量裁判**（每一轮我都亲自浏览器验收后才允许 commit 存盘）。AI 完成的重复劳动包括：RK4 数值积分与物理方程的样板实现、Canvas 渐变发光等渲染细节代码、DOM 事件绑定与 localStorage 读写等胶水代码、以及 Git 命令的自动执行。结论：AI 极大压缩了"语法搬运"的时间，但**需求定义、边界把控与最终质量裁决**始终由人主导——这正是人在回路之上（HOTL）的主体地位。
